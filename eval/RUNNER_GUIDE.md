# 第三项：可配置、可追溯的检索执行器

## 1. 本轮做了什么

现在可以指定“哪套题、哪个快照、哪个测试服务、哪种检索模式”，并把**每条实际请求及返回结果**保存下来。

第三项没有优化算法、调整阈值或运行真实环境基线。第四项现已统一指标口径：旧函数名只作为统一模块的兼容入口；本执行器仍仅记录执行，不自动评分或输出质量门禁。离线评分请用 `score_eval.py`，说明见 [METRICS_GUIDE.md](METRICS_GUIDE.md)。第五项的基线与对比报告尚未实施。

## 2. 使用前提

1. 已装载对应评测集的隔离测试服务，评测期间不继续入库或切换文档版本。
2. 已按该评测集导出并校验真实离线快照，参见 [DATASET_GUIDE.md](DATASET_GUIDE.md)。
3. 通过安全渠道注入查询密钥，不把实际密钥写入共享命令、配置文件或日志。

**本次开发测试中的快照、HTTP响应均为替身，不能拿测试产物当真实效果基线。**

## 3. 运行示例

命令在 `heat-knowledge-service` 根目录运行；先通过安全环境配置提供 `KNOWLEDGE_QUERY_KEY`：

```bash
python eval/run_eval.py \
  --dataset eval/datasets/beijing-v1/manifest.json \
  --snapshot eval/snapshots/beijing-001.json \
  --base http://127.0.0.1:18000 \
  --modes KEYWORD VECTOR HYBRID \
  --top-k 10 \
  --timeout 120 \
  --output-dir eval/runs \
  --run-id trial-001
```

示例地址只代表操作者自己的隔离测试服务，并非自动创建的服务。`--base` 是 API 根地址，客户端追加 `/knowledge/search`，不要重复填写整个检索接口路径。

也可以通过环境变量显式选择地址和快照：

- `KNOWLEDGE_BASE`
- `KNOWLEDGE_EVAL_SNAPSHOT`
- `KNOWLEDGE_QUERY_KEY`

没有服务地址、快照或密钥时直接失败，不请求默认NAS服务，也不使用历史硬编码密钥。不自动读取 `.env`，不把环境变量全集写入产物。

Windows PowerShell 可将命令写成一行，使用 `.venv\Scripts\python.exe`；配置变量使用 `$env:KNOWLEDGE_QUERY_KEY` 等，不在共享文档中填写真实值。

### 参数

| 参数 | 含义 |
|---|---|
| `--dataset` | 标准评测集 manifest，默认 beijing-v1；兼容旧位置参数，但不能同时传两种形式 |
| `--snapshot` | 实际快照；缺省时从显式环境变量读取 |
| `--base` | 测试服务base URL；必须HTTP(S)，禁止URL内凭据、查询参数或片段 |
| `--key-env` | 查询密钥环境变量名，默认 KNOWLEDGE_QUERY_KEY；不接受 `--key` 明文密钥 |
| `--modes` | 默认 KEYWORD、VECTOR、HYBRID，可选择子集；不允许重复模式 |
| `--top-k` | 默认10，范围1..50；同一次实验中全部案例使用相同配置 |
| `--timeout` | 默认120秒，正有限数值；urllib的连接/读取超时，不是严格的总时长预算 |
| `--warmup` | 先执行同一组案例和模式一遍，并将所有暖机请求保存为 WARMUP |
| `--output-dir` | 运行目录的父目录，默认 eval/runs |
| `--run-id` | 可选编号；未提供则生成UTC时间+随机后缀，已有同名目录一律拒绝 |
| `--target-config` | 可选JSON配置留档，不应用到服务、不发送给检索API |

没有自动重试；每条记录 `attempt=1`。普通失败不会隐藏，也不会通过重试换成看似成功的样本。

## 4. 每次保存什么

```text
eval/runs/<run_id>/
├── manifest.json
└── executions.jsonl
```

### manifest.json：这次怎么测

- 运行编号、创建/开始/结束UTC时间、运行状态。
- 服务base URL及实际endpoint；只记密钥环境变量名，不记密钥值。
- 模式、topK、超时、暖机标记、执行顺序、重试次数。
- 评测集身份、版本、split、数量、manifest/案例文件哈希及语料清单。
- 快照身份、语料哈希、文件哈希、创建时间、活动文档版本、数量及已有索引元信息。
- Python/操作系统信息，以及执行器/客户端/案例加载器/证据映射器的源码SHA-256。
- 计划次数、已启动尝试次数、已落盘记录次数、状态计数、降级次数、未完成次数。

这些是执行统计，**不是检索质量分数**。计数包含暖机与正式执行，逐例记录可按 `phase` 区分。降级计数按服务 `meta.degraded` 的非空/真值记录，不自动解释是否是正常的模式禁用或故障；原始说明保留供后续判别。

模式执行顺序、服务缓存和Embedding首次连接都会影响耗时；本轮不把这些记录直接宣称为稳态/冷启动统计。

### executions.jsonl：每道题发生了什么

每行包含：

- `run_id`、递增序号、案例编号、类型、标签、模式、执行阶段。
- 标准行为/证据及本快照映射出的相关chunkId，供后续离线评分。
- 实际请求体：query、地域、类型、有效状态、授权项目、topK、模式。
- 开始/结束时间；客户端HTTP发送、读取、解析及响应格式校验的耗时，不包含结果落盘。
- `outcome`：状态、HTTP状态码、返回JSON正文；不是JSON时记录脱敏文本和失败原因。
- 服务返回的原始meta与单独的降级标记/说明。

响应保存完整解析结构，但会移除凭据信息，**不是逐字节网络备份**。服务没有返回响应时 `body=null`，不能伪装成 `results=[] / noEvidence=true`。

标准证据和相关chunkId只进入本地评测产物，绝不发送给被测检索服务。

## 5. 失败与中止规则

| 情况 | 处理 |
|---|---|
| 评测集/快照/证据预检失败 | PRECHECK_FAILED；保留失败清单和空JSONL，不发出检索请求 |
| 单例超时、网络错误、HTTP非2xx | 保存 TIMEOUT/NETWORK_ERROR/HTTP_ERROR，继续后续案例 |
| JSON/UTF-8/响应字段异常 | 保存 INVALID_RESPONSE 与正文，继续，不算正确拒答 |
| 返回禁止文档、快照外chunk、文档身份/版本不一致 | 先保存 CONTRACT_ERROR 和异常响应，再中止整次运行 |
| 未预期的执行器异常 | 保存 INTERNAL_ERROR（如发生在请求阶段），停止后续请求 |
| Ctrl+C | 尽可能记录 INTERRUPTED 并保留已落盘产物 |
| 写文件失败 | 立即停止请求；尽可能保存FAILED及在途标记，不丢结果后继续运行 |

已解析的响应即使格式错误，也会检查其暴露的文档/chunk身份；不能用错误的 `noEvidence` 字段绕过权限中止规则。

退出码：

- `0`：全部请求正常完成；**不代表质量合格，也不代表没有降级**。
- `1`：完整执行但有请求错误，或执行器/产物写入失败。
- `2`：配置/预检错误、输出目录冲突、数据/权限契约违反导致中止。
- `130`：操作者中断。

每条结果在下一请求前flush/fsync；manifest使用同目录临时文件后替换。请求前保存 `in_flight` 标记，发生写入故障或强杀时，明确指出哪条尝试可能没有完整记录。

强杀、断电或磁盘故障下，持久化程度取决于文件系统，不能保证全部响应完整保存。若manifest仍为RUNNING、保留在途标记或最后一行不完整，视为未完整实验；以完整JSONL记录检查实际落盘情况，不冒充已完成，也不自动接着追加。重新运行必须使用新的目录。

## 6. 被测配置如何留档

快照不能证明当前服务部署的全部配置。推荐额外提供自己确认过的 JSON：

```json
{
  "target_code_commit": "<被测代码版本>",
  "deployment_id": "<隔离测试部署编号>",
  "embedding_model": "<实际模型>",
  "no_evidence_min_similarity": "<实际阈值>",
  "fusion_config": "<实际融合配置>"
}
```

通过 `--target-config <文件>` 记录内容及原文件哈希。清单明确标记这是**操作者声明，未远程验证**；工具不会根据此文件修改服务。缺失的部署信息不自动猜测。

比较方案时，应使用稳定的测试部署和同一评测集版本；切分/Embedding变化需要相应的新索引和快照。留档本身不等于已实现实验可比性判定，完整对比在第五项处理。

## 7. 凭据和资料安全

- 所有评测网络入口已移除旧服务地址/密钥兜底；语料装载的历史模式也不再默认连业务NAS。
- 语料装载只接受管理密钥环境变量，所有模式都要求 `--confirm-test-environment`。
- HTTP客户端禁止自动重定向，避免凭据被转发或被测地址偷偷改变；跨主机连接建议使用HTTPS，禁止重定向本身不提供传输加密。
- 不保存认证头；对常见凭据字段、已配置密钥字面值及常见错误正文中的认证回显脱敏。
- 脱敏不是通用PII识别器。查询、证据、权限信息、响应正文仍可能包含敏感业务数据。
- `eval/runs/` 已加入 `.gitignore`，与快照一样默认不提交；自定义输出目录需自行管理。
- 在支持权限的文件系统上新运行子目录设置为0700；Windows/挂载盘ACL由操作者确认。
- 移除脚本兜底不会轮换服务已有密钥，也不会修改业务服务配置。

第三项曾让阈值脚本复用安全查询客户端。第四项审核发现现有结果已被门槛过滤等问题，旧推荐已停止；`calibrate_threshold.py --audit`只做离线审核，不调用服务、不推荐阈值。详见 METRICS_GUIDE.md。

## 8. 验证范围和暂停约定

本轮新增21个测试，全量81个unittest通过；使用临时Python 3.14环境。覆盖真实CLI的配置、原文/快照预检、三模式与暖机透传、失败继续、契约失败留档后中止、脱敏、原子清单、逐例落盘、目录不覆盖及中断/IO异常。

HTTP传输、数据库与chunk产物均为测试替身，没有访问NAS/真实PostgreSQL、上传语料或调用外部Embedding。尚未生成真实效果基线。
