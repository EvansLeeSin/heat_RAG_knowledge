# 第四项：离线检索评分 V1

## 1. 它做什么、不做什么

`run_eval.py` 仍只调用正常 `/knowledge/search` 并保存记录；`score_eval.py` 在接口之外读取这些记录，与标准证据比较。评分器不调用网络、数据库、Embedding或LLM，不把标准答案传入服务，不修改召回、排序或阈值。正常用户请求不经过这些工具。

评分器交付确定性检索指标、逐案例持久化与按模式的数值汇总；不是最终回答评分，也不生成发布门禁。第五项已新增独立的基线/A-B报告工具，见 [REPORT_GUIDE.md](./REPORT_GUIDE.md)。两套现有评测集仍为development，不能将指标可计算当作冻结验收通过。

## 2. 使用

在 `heat-knowledge-service` 根目录，先完成第三项执行并得到运行目录，再评分：

```bash
python eval/score_eval.py --run-dir "eval/runs/替换为真实运行编号"
```

评分不需要服务地址或密钥。原始评测集、配套语料和快照必须仍可读取；搬迁后可以指定原文件的新位置：

```bash
python eval/score_eval.py --run-dir "eval/runs/替换为真实运行编号" \
  --dataset eval/datasets/beijing-v1/manifest.json \
  --snapshot "替换为原快照的路径.json" --score-id metrics-v1
```

新位置的文件必须和执行时哈希一致，不能以新的题库、快照重解释旧结果。Windows可将 `python` 替换成 `.venv/Scripts/python` 并使用相应shell的续行方式。

每次重评生成独立批次，同名目录（包括不完整目录）拒绝覆盖：

```text
runs/<run_id>/
├── manifest.json              # 原执行清单：不修改
├── executions.jsonl           # 原执行记录：不修改
└── scores/<score_id>/
    ├── manifest.json          # 口径版本、源码/输入/产物哈希、完成状态
    ├── scores.jsonl           # 每个计划中的正式案例×模式一行
    └── metrics.json           # 按模式的指标、分母、覆盖率及耗时
```

退出码：`0`=所有适用指标完整可算（不等于业务质量合格）；`1`=已保存评分，但部分指标不可算/存在未完成执行或评分故障；`2`=输入不可信、同名输出存在或写入失败。写入失败批次的清单可能停留在PREPARING，不能作为完成的评分使用。批次完成清单最后原子发布，并记录scores/metrics的SHA256。

## 3. 质量指标定义

| 指标 | 范围、公式与边界 |
|---|---|
| Recall@5 | 仅K/S正样本。前5个原始位置中不同正确chunk数 / 全部标准证据chunk数；分母不是5。 |
| MRR@10 | 仅正样本。前10个原始位置中首次命中的倒数；未命中为0，第11条命中仍为0。 |
| nDCG@10 | 仅正样本、二元相关性。首次出现的正确chunk增益为1/log2(rank+1)，重复增益为0；IDCG按min(标准证据数,10)计算。 |
| 正样本无证据率 | 正样本中正常可判定响应的noEvidence=true比例；越低越好。工程故障、通路健康不明不是已判定拒答。 |
| 负样本无证据率 | N样本中正常可判定响应的noEvidence=true比例；越高越好。不把超时、报错或不明原因的向量空结果算成正确拒答。 |

金标准仍从原数据集的“文档+原文”与原快照重新映射成chunkId，不直接信任执行文件里保存的标签。评分按接口返回的顺序，不按score重排，也不把score当作质量或置信度。Recall是**chunk级**召回，不是语义正确性、原文证据覆盖率或最终回答正确性；重新切分可能改变gold chunk数，因此跨切分比较不能只依据这一个数值。

重复chunk保留原排名位置，不能通过去重压缩排名“提高”分数。例如 `[A,A,B]`、gold=`{A,B}`，Recall@2为0.5，第二个A占位但不得分。返回长度少于10不代表@10无法计算：只要请求topK≥10，较短有效结果视为后续无命中；但**请求topK<10时，MRR@10/nDCG@10为null**，不能冒充完整的@10实验。@5同理。

没有标准正证据的N样本，排名指标是N/A（null），不是0。成功请求返回空结果且noEvidence=true：正样本排名指标为0；拒答质量是否可判定还要经过通路状态审查。

## 4. 完整分母与未知值

评分按“数据集全部案例×所选模式”的正式网格生成，不删除请求故障、未执行或未落盘的案例。只接受原执行器合法的顺序前缀；重复行、丢失中间行、顺序改变、标签/请求变化、成功状态却实际协议失败等导致整体评分中止。已正确留档的CONTRACT_ERROR可以生成失败审计，但该案例不得分，后续未执行项继续占据计划网格，不能作为有效完整质量基线。

每个质量汇总包含：

- `expected_count`：该指标适用的完整计划案例数；
- `scored_count` / `unscored_count`：已判定/未知数；
- `value`：只有全部适用案例都可判定才给出正式均值，否则null；
- `observed_subset_mean`：明确标为已判定子集的诊断均值，不是完整实验得分；
- `full_set_bounds`：未知值在0..1时，完整分母均值的上下界；
- `complete`：该指标是否可完整计算；没有适用案例时为false、value=null。

例如两个正样本，一个Recall=1、一个超时：value=null，expected=2，scored=1，子集均值=1，完整界限=[0.5,1]。不能据此宣传100%召回。这里的界限是未知值范围，**不是统计置信区间**。

执行器与评分器共用响应协议校验：空/非空结果与noEvidence声明矛盾属于INVALID_RESPONSE，不能算正确拒答；旧成功记录若有此矛盾则拒绝评分。`execution_status`保留HTTP/协议/契约故障；`score_status=SCORING_ERROR`标识评分函数异常，和服务失败不同。指标返回NaN等非法数值也按评分故障留档。未落盘但有in-flight标记的正式请求标为UNRECORDED_ATTEMPT；之后真正未开始的项为NOT_EXECUTED。

`quality_complete`只表示所有适用指标有足够数据，并不表示质量好、数据集覆盖充分或发布验收通过。本项不输出统计显著性结论。

## 5. 工程指标及当前服务的限制

- `success_rate`：正式HTTP与响应协议成功数 / 全部正式计划请求数；未执行也在分母。它不是“向量后端健康率”。
- `reported_degradation_rate`：成功响应中声明降级的数量 / 全部正式计划请求数，同时提供可观测成功数。主动禁用非所选通路（字典值disabled/disabled_by_mode）不算降级；没有degraded字段仅是“未声明”，不是健康证明。
- 当前服务的 `keyword channel empty` / `vector channel skipped` 不能稳定区分正常空命中和真实通路故障。因此只报告**声明降级率**，不捏造通路故障率。
- 当前 `vector_search()` 将EmbeddingError转换为空列表；VECTOR/HYBRID完全空命中且缺少gate.bestSimilarity时，不能证明向量通路正常。noEvidence=true的此类记录标为VECTOR_EMPTY_HEALTH_UNVERIFIED，拒答质量指标为null，而非正确拒答。已有有限的过滤前相似度且无声明降级时才有依据判定。非空结果的实际排名仍可评分。
- 有声明降级的空结果同样不作为确定的正确拒答；降级但返回非空结果，可评实际召回及观察到的noEvidence=false。

这是利用**现有响应**的保守处理，没有修改主流程去识别eval，也没有增加通路健康采集。要进一步分清原因，需要之后另行授权补充通用诊断数据。

### 耗时

WARMUP不参与任何正式质量、成功率或延迟指标，但批次清单保留暖机记录数量与状态计数。暖机本身故障且正式运行恢复时，不把暖机故障算成正式失败。

按模式分别提供成功请求、未声明降级的成功请求、全部已留档请求（包括故障）的P50/P95与样本数；缺失请求没有凭空生成耗时。单位秒。分位数采用线性插值：位置=(N-1)q，P50为通常的中位数；空样本为null、单样本为自身。

记录时长是第三项HTTP调用时间，包含网络和响应解析，不包含落盘/评分，也不是内部召回各阶段耗时。固定的模式执行顺序可能让VECTOR预热HYBRID的Embedding缓存；这些数字不能直接宣称独立冷启动性能提升。本项不改变执行顺序，后续比较必须检查这些条件。

## 6. 阈值标定审核

```bash
python eval/calibrate_threshold.py --audit
```

审核成功退出0；不加--audit表示想做标定，但当前缺少可靠数据，退出2，**不发检索请求、不推荐或应用阈值**。历史数据集位置参数仍能解析，但不会触发标定。

审核结论：旧推荐已禁用。依据是 `app/services/search.py`（命令打印当前源码SHA256，不是自动证明未来代码仍具有相同语义；检索代码变化后需重审）：

1. 结果已通过现行门槛；低于门槛的正确证据不可见，不能评估更低门槛。
2. gate.bestSimilarity只有候选整体最佳值，四位小数；没有每条标准证据的过滤前分数。
3. VECTOR仍会插入精确条款，EXACT_MATCH的1.0不是向量距离，不能全部使用1-score。
4. 原脚本把未入top50的正样本排除出分母；top50也不是全库候选分布。
5. 原脚本将空结果设为相似度0，可能把基础设施故障算成完美拒答。
6. 无正/负样本或全部正样本未命中还会触发空集统计错误。

可靠标定至少需要受控的门槛前候选、真实scoreType、标准证据分数覆盖和通路状态，以及固定完整分母。本轮不新增这些生产接口或导出能力，也不自动调参。
